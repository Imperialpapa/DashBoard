# GitHub 베스트

기간별로 새로 만들어진 GitHub 공개 저장소를 스타순으로 보여 주는 대시보드입니다. 주간·월간·연간 단위로, "최근 7일" 같은 이동 구간과 지난 주·달·해를 골라 볼 수 있습니다.

**보기: <https://imperialpapa.github.io/DashBoard/>**

서버 없이 돌아갑니다. GitHub Actions가 하루 두 번(한국 시간 9시와 21시 무렵) GitHub 검색 API로 순위를 받아 JSON으로 만들고, GitHub Pages가 그 파일과 화면을 정적으로 내보냅니다. 열어 둔 화면은 다음 수집 예정 시각이 지난 뒤에만 새 판이 나왔는지 확인합니다(그때부터 10분 간격).

## 돌아가는 방식

`.github/workflows/pages.yml`이 예약 실행(하루 두 번), `main` 푸시, 수동 실행 때마다 `npm run build`를 돌려 `site/` 폴더를 만들고 Pages에 배포합니다.

빌드(`lib/build.js`)는 매번 새 기계에서 돌기 때문에, 지난번 배포본에 함께 올려 둔 수집 상태(`data/state/`)를 내려받아 이어서 시작합니다. 그래서 스타 증가와 순위 변동을 계산할 수 있고, 지난 기간을 매번 다시 받지 않습니다. 한 번의 빌드에서 시간 안에 못 받은 기간은 다음 빌드가 이어 받습니다.

알아 둘 점:

- GitHub의 예약 실행은 붐빌 때 늦어지거나 건너뛸 수 있습니다. 한참 갱신이 없으면 화면 위쪽에 표시됩니다.
- 공개 저장소에 60일 동안 활동이 없으면 GitHub이 예약 실행을 끕니다. Actions 탭에서 다시 켜면 됩니다.
- 이 저장소를 포크해 쓰려면 Settings → Pages → Source를 "GitHub Actions"로 바꾸세요.

## 순위를 만드는 방법

- 해당 기간(UTC 기준)에 만들어진 공개 저장소를 스타 내림차순으로 검색한 결과 상위 100개입니다. 기간 안에 만들어진 저장소만 다루므로 스타 수가 곧 그 기간에 받은 스타입니다.
- "증가"와 순위 변동은 앞서 수집해 둔 스냅샷과 비교한 값입니다(하루 두 번 수집이면 약 하루 전과 비교).
- 최근 구간은 빌드할 때마다, 지난 구간은 하루~7일에 한 번 다시 확인합니다.
- 한도를 넘거나 요청이 실패하면 기존 데이터를 그대로 두고 다음 빌드에서 다시 시도합니다.

### 스팸 의심 숨기기

최근 구간의 스타순 검색 결과에는 스타를 사들인 저장소가 대량으로 섞입니다(스타 1,200개에 포크 0개인 저장소가 같은 날 수십 개씩 생기는 식). 그래서 다음 조건에 모두 해당하는 저장소를 스팸으로 의심합니다.

- 스타 100개 이상
- 포크가 스타의 0.5% 미만
- 2020년 이후 생성(오래된 저장소에는 포크 없이 스타만 많은 정상 라이브러리가 있어서 제외)

스팸 의심은 기본으로 숨기고, 그만큼 아래 순위를 더 받아(기간당 최대 5쪽) 100개를 채웁니다. 숫자만 보는 어림 규칙이라 틀릴 수 있으므로 지우지는 않습니다. 화면의 "스팸 의심 숨기기"를 끄면 표시가 붙은 채로 원래 순위를 볼 수 있습니다.

## 내 컴퓨터에서 돌리기

Node.js 18 이상이 필요하고, 설치할 패키지는 없습니다.

```sh
npm start        # 로컬 서버: http://127.0.0.1:4173
npm run build    # 정적 사이트를 site/ 에 만든다
npm test         # 로직 시험(GitHub를 부르지 않는다)
```

로컬 서버는 같은 화면을 쓰되, 백그라운드에서 계속 수집하면서 바뀐 순위를 실시간으로 밀어 주고(SSE), 목록에 없는 오래된 기간도 열 때 받아 옵니다.

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `GITHUB_TOKEN` (또는 `GH_TOKEN`) | 없음 | 있으면 검색 한도가 분당 10회에서 30회로 늘어납니다. 권한(scope)은 필요 없습니다 |
| `PORT`, `HOST` | `4173`, `127.0.0.1` | 로컬 서버 주소 |
| `SEED_URL` | 없음 | 빌드가 수집 상태를 이어받을 배포본 주소(Actions가 넣어 줍니다) |
| `BUDGET_SEC` | 540 | 빌드 한 번이 수집에 쓰는 시간 상한(초) |

갱신 주기, 기간 목록 길이, 스팸 의심 기준 같은 값은 `config.js`에서 바꿉니다. 수집 시각을 바꾸려면 워크플로의 `cron`(UTC)과 `config.js`의 `static.every`·`static.at`을 함께 바꿉니다.

## 구조

```
.github/workflows/pages.yml  예약 실행: 수집 → 정적 사이트 → Pages 배포
scripts/build.js             정적 사이트 빌드 실행
lib/build.js                 빌드: 지난 배포본에서 상태 이어받기, 수집, 파일 쓰기
lib/collector.js             수집기: 우선순위, 한도 관리, 백오프
lib/store.js                 순위 캐시, 증가·순위 변동 계산
lib/periods.js               기간(버킷) 정의와 갱신 주기
lib/github.js                GitHub 검색 API 호출
lib/spam.js                  스팸 의심 판정
public/                      화면(HTML·CSS·JS, 빌드 과정 없음)
server.js                    로컬 서버(실시간 푸시, 수동 갱신)
config.js                    설정
test/                        로직 시험
```

`data/`(로컬 캐시)와 `site/`(빌드 결과)는 실행하면서 생기며 저장소에 올리지 않습니다.
