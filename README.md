# GitHub · Hugging Face · Hacker News · App Store 베스트

기간별로 새로 만들어진 GitHub 공개 저장소를 스타순으로, Hugging Face 공개 모델·Space·데이터셋을 좋아요순으로, Hacker News에 올라온 글을 점수순으로, 그리고 한국 App Store 인기 차트를 보여 주는 대시보드입니다. 화면 위쪽 탭으로 넷을 오갑니다. GitHub·Hugging Face·Hacker News는 주간·월간·연간 단위로 "최근 7일" 같은 이동 구간과 지난 주·달·해를 골라 보고, App Store는 무료·유료·최고 매출 차트를 카테고리별로 골라 봅니다.

**보기: <https://imperialpapa.github.io/DashBoard/>**

화면 위쪽의 **홈 화면에 추가** 단추로 휴대폰 홈 화면이나 PC 바탕 화면에 앱처럼 둘 수 있습니다. 브라우저가 설치 창을 띄울 수 있다고 알려 오면(Chrome·Edge 등) 누를 때 그 창이 뜨고, 그렇지 않은 휴대폰 브라우저(iPhone·iPad, 삼성 인터넷, 이미 추가했거나 막 연 Chrome)에서는 브라우저 메뉴의 "홈 화면에 추가"로 넣는 방법을 알려 줍니다. 휴대폰에서는 단추가 늘 보이고, PC에서는 설치 창을 띄울 수 있는 브라우저에서만 보입니다(Firefox 등에는 없습니다). 이미 홈 화면에서 연 화면에는 나타나지 않습니다. 홈 화면에서 열어도 순위는 그때그때 받아 오므로 인터넷 연결이 있어야 합니다.

서버 없이 돌아갑니다. GitHub Actions가 하루 두 번(한국 시간 9시와 21시 무렵) GitHub 검색 API, Hugging Face 모델 목록 API, Hacker News 검색 API, 애플의 공개 차트 피드로 순위를 받아 JSON으로 만들고, GitHub Pages가 그 파일과 화면을 정적으로 내보냅니다. 열어 둔 화면은 다음 수집 예정 시각이 지난 뒤에만 새 판이 나왔는지 확인합니다(그때부터 10분 간격).

## 돌아가는 방식

`.github/workflows/pages.yml`이 예약 실행(하루 두 번), `main` 푸시, 수동 실행 때마다 `npm run build`를 돌려 `site/` 폴더를 만들고 Pages에 배포합니다.

빌드(`lib/build.js`)는 매번 새 기계에서 돌기 때문에, 지난번 배포본에 함께 올려 둔 수집 상태(`data/state/`)를 내려받아 이어서 시작합니다. 그래서 스타 증가와 순위 변동을 계산할 수 있고, 지난 기간을 매번 다시 받지 않습니다. 한 번의 빌드에서 시간 안에 못 받은 기간은 다음 빌드가 이어 받습니다.

### 수집 주기: 하루 두 번 이상, 한 시간에 한 번 이하

수집은 이 범위를 벗어나지 않습니다(`config.js`의 `collect: { minGap: 1시간, maxGap: 12시간 }`).

- **하루 두 번 이상**: 예약 실행이 12시간 간격으로 돕니다. 진행 중인 기간(최근 N일, 이번 주·달·해)과 차트는 그때마다 다시 받습니다. 끝난 기간은 순위가 거의 바뀌지 않아 6시간~7일에 한 번만 다시 확인합니다.
- **한 시간에 한 번 이하**: 푸시나 수동 실행으로 빌드가 잇달아 돌아도, 받은 지 한 시간이 안 된 것은 다시 받지 않고 지난 배포본에서 이어받은 순위를 그대로 싣습니다. 화면 파일만 새로 나가고, 화면의 "마지막 수집" 시각도 그대로입니다. 출처마다 따로 따지므로 새로 켠 탭은 바로 받습니다.
- 로컬 서버와 '지금 갱신' 단추도 같은 범위를 따릅니다. `config.js`에 범위 밖의 주기를 적으면 범위 안으로 맞춰지고, 예약 간격이 범위를 벗어나면 `npm test`가 실패합니다.

알아 둘 점:

- GitHub의 예약 실행은 붐빌 때 늦어지거나 건너뛸 수 있습니다. 한참 갱신이 없으면 화면 위쪽에 표시됩니다.
- 지난 배포본을 내려받다가 실패하면(Pages가 잠깐 503을 내는 때가 있습니다) 그 파일을 세 번까지 다시 받습니다. 그래도 안 되면 쌓아 온 이력을 빈 것으로 덮어쓰지 않도록 빌드를 실패로 끝내고, 사이트는 지난 배포본 그대로 남습니다. Actions 탭에서 다시 실행하면 됩니다.
- 공개 저장소에 60일 동안 활동이 없으면 GitHub이 예약 실행을 끕니다. Actions 탭에서 다시 켜면 됩니다.
- 이 저장소를 포크해 쓰려면 Settings → Pages → Source를 "GitHub Actions"로 바꾸세요.

## 순위를 만드는 방법

- 해당 기간(UTC 기준)에 만들어진 공개 저장소를 스타 내림차순으로 검색한 결과 상위 100개입니다. 기간 안에 만들어진 저장소만 다루므로 스타 수가 곧 그 기간에 받은 스타입니다.
- "증가"와 순위 변동은 앞서 수집해 둔 스냅샷과 비교한 값입니다(하루 두 번 수집이면 약 하루 전과 비교).
- 정렬을 "포크순"으로 바꾸면 이 100개를 포크가 많은 순으로 다시 줄 세웁니다. 포크순으로 따로 검색한 순위가 아니므로, 스타 상위 100개에 들지 못한 저장소는 포크가 많아도 나오지 않습니다.
- 최근 구간은 수집할 때마다(하루 두 번), 지난 구간은 6시간~7일에 한 번 다시 확인합니다.
- 한도를 넘거나 요청이 실패하면 기존 데이터를 그대로 두고 다음 빌드에서 다시 시도합니다.

### 스팸 의심 숨기기

최근 구간의 스타순 검색 결과에는 스타를 사들인 저장소가 대량으로 섞입니다(스타 1,200개에 포크 0개인 저장소가 같은 날 수십 개씩 생기는 식). 그래서 다음 조건에 모두 해당하는 저장소를 스팸으로 의심합니다.

- 스타 100개 이상
- 포크가 스타의 0.5% 미만
- 2020년 이후 생성(오래된 저장소에는 포크 없이 스타만 많은 정상 라이브러리가 있어서 제외)

스팸 의심은 기본으로 숨기고, 그만큼 아래 순위를 더 받아(기간당 최대 5쪽) 100개를 채웁니다. 숫자만 보는 어림 규칙이라 틀릴 수 있으므로 지우지는 않습니다. 화면의 "스팸 의심 숨기기"를 끄면 표시가 붙은 채로 원래 순위를 볼 수 있습니다.

### Hugging Face 탭

탭 안에서 **모델 · Spaces · 데이터셋**을 오갑니다. Hugging Face API에는 "이 기간에 만들어진 것만" 거르는 조건이 없습니다. 그래서 종류마다 목록을 좋아요순으로 한 번 훑어 내려가며(한 번에 1,000개씩, 최대 60번), 각 항목을 만든 날짜가 속한 주·달·해에 나눠 담습니다. 목록이 좋아요순이므로 기간마다 먼저 담긴 100개가 그 기간의 상위 100개입니다.

- 한 번 훑으면 그 종류의 모든 기간이 함께 갱신됩니다. 종류마다 수십 초쯤 걸리고 토큰 없이도 됩니다. 세 종류가 같은 요청 한도(익명 5분에 500회)를 나눠 쓰므로 빌드에서는 동시에 받지 않고 차례로 받습니다.
- 60번을 받고도 100개가 안 찬 기간(막 시작한 주 등)은 찬 만큼만 보여 주고, 좋아요 몇 개 이상까지 훑었는지를 함께 적습니다.
- 2022년 3월 이전에 만든 것은 만든 날짜가 모두 같은 날로 기록돼 있어, 2023년부터만 다룹니다.
- 포크가 없어 스팸 의심 규칙은 적용하지 않습니다. 대신 모델은 작업 종류·라이브러리·최근 30일 다운로드 수를, Space는 무엇으로 만들었는지(SDK: Gradio·Docker·Static 등)를, 데이터셋은 데이터의 형태(text·image·audio 등)와 다운로드 수를 보여 줍니다.
- 모델과 데이터셋은 정렬을 "다운로드순"으로 바꾸면 순위에 든 것을 최근 30일 다운로드가 많은 순으로 다시 줄 세웁니다. 다운로드순으로 따로 훑은 순위가 아니므로, 좋아요 상위 100개에 들지 못한 것은 다운로드가 많아도 나오지 않습니다. 다운로드 수가 없는 Spaces에는 이 정렬이 없습니다.
- 한 종류의 수집이 실패해도 나머지는 그대로 배포되고, 실패한 종류는 지난번 순위를 실패 표시와 함께 보여 줍니다.
- 다룰 종류는 `config.js`의 `hf.kinds`에서 고릅니다.

### Hacker News 탭

Hacker News 검색 API(Algolia 제공)는 올라온 시각으로 범위를 걸면 점수 내림차순으로 돌려줍니다. 그래서 GitHub 탭과 같은 방식으로, 기간마다 한 번 검색한 상위 100개가 그 기간의 순위입니다.

- 토큰이 필요 없고 한도가 넉넉해, 기간 87개를 몇 개씩 동시에 받습니다. 처음에는 10초 남짓, 그 뒤로는 진행 중인 기간(최근 7일·이번 주 등 6개)과 다시 확인할 때가 된 지난 기간만 받습니다.
- 연간은 2007년부터 있습니다. 채용 공고와 설문은 빠집니다.
- 제목은 원문으로, "댓글"은 Hacker News의 토론으로 이어집니다. 본문만 있는 글(Ask HN 등)은 제목도 토론으로 갑니다.
- 정렬을 "댓글순"으로 바꾸면 순위에 든 글을 댓글이 많은 순으로 다시 줄 세웁니다. 댓글순으로 따로 검색한 순위가 아니므로, 점수 상위 100개에 들지 못한 글은 댓글이 많아도 나오지 않습니다.
- 언어 자리에는 원문 사이트(도메인)를 보여 주고, 그것으로 거르거나 찾을 수 있습니다.
- "그 기간에 올라온 글 N개 가운데"의 N은 API가 정확히 세어 준 때만 적습니다. 글이 많은 기간은 어림값만 오는데 실제와 차이가 커서 쓰지 않습니다.
- 일부 기간만 받지 못하면 그 기간만 지난번 순위를 두고 표시를 남깁니다.

### App Store 탭

애플은 "이 기간에 나온 앱을 인기순으로" 주는 목록을 제공하지 않습니다. 대신 인기 차트(무료·유료·최고 매출)를 종합과 카테고리별로 100위까지 공개 피드로 줍니다. 그래서 이 탭은 기간이 아니라 차트 종류와 카테고리를 고르는 방식이고, 순위는 애플이 매긴 차트 순서 그대로입니다.

- 차트 3종 × (종합 + 카테고리 24개) = 75개 차트를 한 번에 받습니다. 요청 100여 번에 2~3분쯤 걸리고 토큰이 필요 없습니다.
- 차트에 나온 앱의 평가 수와 별점은 애플의 조회 API로 200개씩 묶어 받아 옵니다. "평가" 칸은 누적 평가 수, "증가"는 앞선 스냅샷 이후 늘어난 평가 수입니다.
- 순위 변동과 "NEW"(차트에 새로 진입)는 앞서 수집한 스냅샷과 비교한 값입니다(약 하루 전).
- 새 앱만 보려면 "출시" 거르기(최근 7일·30일·1년)를 씁니다. 오른쪽 차트는 순위에 든 앱의 출시 연도 분포입니다.
- 차트 순위는 애플의 집계(다운로드 속도 등)를 따르므로 평가 수 순서와 다릅니다. 정렬을 "평가 증가순"으로 바꾸면 최근 평가가 많이 붙은 앱을 볼 수 있습니다.
- 일부 차트만 받지 못하면 그 차트만 지난번 순위를 두고 표시를 남깁니다. App Store 수집이 통째로 실패해도 나머지 탭은 그대로 배포됩니다.
- 기본은 한국 스토어입니다. 다른 나라는 `config.js`의 `as.country`(예: `us`, `jp`)를 바꿉니다.

Google Play는 공식 차트 API가 없고 웹 페이지를 긁는 것은 약관 위반이라 다루지 않습니다.

## 내 컴퓨터에서 돌리기

Node.js 18 이상이 필요하고, 설치할 패키지는 없습니다.

```sh
npm start        # 로컬 서버: http://127.0.0.1:4173
npm run build    # 정적 사이트를 site/ 에 만든다
npm test         # 로직 시험(바깥 API를 부르지 않는다)
```

로컬 서버는 같은 화면을 쓰되, 백그라운드에서 수집하면서(진행 중인 기간은 한 시간에 한 번, 보는 사람이 없으면 더 드물게) 바뀐 순위를 실시간으로 밀어 주고(SSE), 목록에 없는 오래된 기간도 열 때 받아 옵니다.

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `GITHUB_TOKEN` (또는 `GH_TOKEN`) | 없음 | 있으면 검색 한도가 분당 10회에서 30회로 늘어납니다. 권한(scope)은 필요 없습니다 |
| `HF_TOKEN` | 없음 | Hugging Face 토큰. 없어도 됩니다(익명 한도 5분에 500회, 세 종류를 훑는 데 180회 이하) |
| `PORT`, `HOST` | `4173`, `127.0.0.1` | 로컬 서버 주소 |
| `SEED_URL` | 없음 | 빌드가 수집 상태를 이어받을 배포본 주소(Actions가 넣어 줍니다) |
| `BUDGET_SEC` | 540 | 빌드 한 번이 수집에 쓰는 시간 상한(초) |

갱신 주기, 기간 목록 길이, 스팸 의심 기준 같은 값은 `config.js`에서 바꿉니다. Hugging Face, Hacker News, App Store 탭을 빼려면 `config.js`의 `hf`, `hn`, `as`를 `null`로 둡니다. 수집 시각을 바꾸려면 워크플로의 `cron`(UTC)과 `config.js`의 `static.every`·`static.at`을 함께 바꿉니다(회차 사이는 1시간 이상 12시간 이하).

## 구조

```
.github/workflows/pages.yml  예약 실행: 수집 → 정적 사이트 → Pages 배포
scripts/build.js             정적 사이트 빌드 실행
lib/build.js                 빌드: 지난 배포본에서 상태 이어받기, 수집, 파일 쓰기
lib/collector.js             GitHub 수집기: 우선순위, 한도 관리, 백오프
lib/sources.js               GitHub 말고 덧붙는 출처 목록(hf·hfs·hfd, hn, as): 서버와 빌드가 이것으로 수집기를 만든다
lib/sweep.js                 한 번 훑어 모든 목록을 갱신하는 수집기의 공통 뼈대
lib/hfcollector.js           Hugging Face 수집기: 좋아요순 목록을 훑어 기간에 나눠 담기
lib/hncollector.js           Hacker News 수집기: 기간마다 점수순으로 검색
lib/ascollector.js           App Store 수집기: 차트 피드를 받고 평가 수를 묶어 조회
lib/store.js                 순위 캐시, 증가·순위 변동 계산
lib/periods.js               기간(버킷) 정의와 갱신 주기
lib/github.js                GitHub 검색 API 호출
```
