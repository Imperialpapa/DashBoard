# GitHub · Hugging Face · Hacker News · App Store 베스트

기간별로 새로 만들어진 GitHub 공개 저장소를 스타순으로, Hugging Face 공개 모델·Space·데이터셋을 좋아요순으로, Hacker News에 올라온 글을 점수순으로, 그리고 한국 App Store 인기 차트를 보여 주는 대시보드입니다. 화면 위쪽 탭으로 넷을 오갑니다. GitHub·Hugging Face·Hacker News는 주간·월간·연간 단위로 "최근 7일" 같은 이동 구간과 지난 주·달·해를 골라 보거나, 그 옆의 네 번째 탭(최대 스타·최대 좋아요·최대 점수)에서 만든 때를 가리지 않고 지금까지 가장 많이 받은 100개를 봅니다. App Store는 무료·유료·최고 매출 차트를 카테고리별로 골라 봅니다. GitHub·Hugging Face·Hacker News에서는 **분야** 단추(에이전트 AI, 로보틱스 등)로 그 분야 것만 모은 순위를 볼 수 있고, 분야는 화면에서 낱말을 적어 바로 더할 수 있습니다. 맨 앞의 **모아 보기** 탭에서는 고른 기간·분야의 순위를 여러 곳 것을 한 화면에 나란히 봅니다.

**보기: <https://imperialpapa.github.io/DashBoard/>**

화면 위쪽의 **홈 화면에 추가** 단추로 휴대폰 홈 화면이나 PC 바탕 화면에 앱처럼 둘 수 있습니다. 브라우저가 설치 창을 띄울 수 있다고 알려 오면(Chrome·Edge 등) 누를 때 그 창이 뜨고, 그렇지 않은 휴대폰 브라우저(iPhone·iPad, 삼성 인터넷, 이미 추가했거나 막 연 Chrome)에서는 브라우저 메뉴의 "홈 화면에 추가"로 넣는 방법을 알려 줍니다. 휴대폰에서는 단추가 늘 보이고, PC에서는 설치 창을 띄울 수 있는 브라우저에서만 보입니다(Firefox 등에는 없습니다). 이미 홈 화면에서 연 화면에는 나타나지 않습니다. 홈 화면에서 열어도 순위는 그때그때 받아 오므로 인터넷 연결이 있어야 합니다.

화면은 밝은 화면으로 열립니다. 오른쪽 위의 달 모양 단추를 누르면 어두운 화면으로 바뀌고(해 모양 단추를 누르면 다시 밝은 화면), 고른 쪽을 그 브라우저가 기억합니다.

서버 없이 돌아갑니다. GitHub Actions가 하루 두 번(한국 시간 9시와 21시 무렵) GitHub 검색 API, Hugging Face 모델 목록 API, Hacker News 검색 API, 애플의 공개 차트 피드로 순위를 받아 JSON으로 만들고, GitHub Pages가 그 파일과 화면을 정적으로 내보냅니다. 열어 둔 화면은 다음 수집 예정 시각이 지난 뒤에만 새 판이 나왔는지 확인합니다(그때부터 10분 간격).

## 돌아가는 방식

`.github/workflows/pages.yml`이 예약 실행(하루 두 번), `main` 푸시, 수동 실행 때마다 `npm run build`를 돌려 `site/` 폴더를 만들고 Pages에 배포합니다.

빌드(`lib/build.js`)는 매번 새 기계에서 돌기 때문에, 지난번 배포본에 함께 올려 둔 수집 상태(`data/state/`)를 내려받아 이어서 시작합니다. 그래서 스타 증가와 순위 변동을 계산할 수 있고, 지난 기간을 매번 다시 받지 않습니다. 한 번의 빌드에서 시간 안에 못 받은 기간은 다음 빌드가 이어 받습니다.

### 수집 주기: 하루 두 번 이상, 한 시간에 한 번 이하

수집은 이 범위를 벗어나지 않습니다(`config.js`의 `collect: { minGap: 1시간, maxGap: 12시간 }`).

- **하루 두 번 이상**: 예약 실행이 12시간 간격으로 돕니다. 진행 중인 기간(최근 N일, 이번 주·달·해, 전체 기간)과 차트는 그때마다 다시 받습니다. 끝난 기간은 순위가 거의 바뀌지 않아 6시간~7일에 한 번만 다시 확인합니다.
- **한 시간에 한 번 이하**: 푸시나 수동 실행으로 빌드가 잇달아 돌아도, 받은 지 한 시간이 안 된 것은 다시 받지 않고 지난 배포본에서 이어받은 순위를 그대로 싣습니다. 화면 파일만 새로 나가고, 화면의 "마지막 수집" 시각도 그대로입니다. 출처마다 따로 따지므로 새로 켠 탭은 바로 받습니다.
- 로컬 서버와 '지금 갱신' 단추도 같은 범위를 따릅니다. `config.js`에 범위 밖의 주기를 적으면 범위 안으로 맞춰지고, 예약 간격이 범위를 벗어나면 `npm test`가 실패합니다.

알아 둘 점:

- GitHub의 예약 실행은 붐빌 때 늦어지거나 건너뛸 수 있습니다. 한참 갱신이 없으면 화면 위쪽에 표시됩니다.
- 지난 배포본을 내려받다가 실패하면(Pages가 잠깐 503을 내는 때가 있습니다) 그 파일을 세 번까지 다시 받습니다. 그래도 안 되면 쌓아 온 이력을 빈 것으로 덮어쓰지 않도록 빌드를 실패로 끝내고, 사이트는 지난 배포본 그대로 남습니다. Actions 탭에서 다시 실행하면 됩니다.
- 공개 저장소에 60일 동안 활동이 없으면 GitHub이 예약 실행을 끕니다. Actions 탭에서 다시 켜면 됩니다.
- 이 저장소를 포크해 쓰려면 Settings → Pages → Source를 "GitHub Actions"로 바꾸세요.

## 순위를 만드는 방법

- 해당 기간(UTC 기준)에 만들어진 공개 저장소를 스타 내림차순으로 검색한 결과 상위 100개입니다. 기간 안에 만들어진 저장소만 다루므로 스타 수가 곧 그 기간에 받은 스타입니다.
- "증가"와 순위 변동은 앞서 수집해 둔 스냅샷과 비교한 값입니다(하루 두 번 수집이면 약 하루 전과 비교).
- 정렬을 "포크순"으로 바꾸면 이 100개를 포크가 많은 순으로 다시 줄 세웁니다. 포크순으로 따로 검색한 순위가 아니므로, 스타 상위 100개에 들지 못한 저장소는 포크가 많아도 나오지 않습니다.
- "최대 스타" 탭은 만든 때를 가리지 않고 같은 방식으로 검색한 결과로, 지금까지 스타를 가장 많이 받은 공개 저장소 100개입니다. 기간이 하나뿐이라 앞뒤로 넘길 것이 없고, 오른쪽 그림은 순위에 든 저장소가 만들어진 해의 분포를 보여 줍니다.
- 최근 구간과 전체 기간은 수집할 때마다(하루 두 번), 지난 구간은 6시간~7일에 한 번 다시 확인합니다.
- 한도를 넘거나 요청이 실패하면 기존 데이터를 그대로 두고 다음 빌드에서 다시 시도합니다.

### 스팸 의심 숨기기

최근 구간의 스타순 검색 결과에는 스타를 사들인 저장소가 대량으로 섞입니다(스타 1,200개에 포크 0개인 저장소가 같은 날 수십 개씩 생기는 식). 그래서 다음 조건에 모두 해당하는 저장소를 스팸으로 의심합니다.

- 스타 100개 이상
- 포크가 스타의 0.5% 미만
- 2020년 이후 생성(오래된 저장소에는 포크 없이 스타만 많은 정상 라이브러리가 있어서 제외)

스팸 의심은 기본으로 숨기고, 그만큼 아래 순위를 더 받아(기간당 최대 5쪽) 100개를 채웁니다. 숫자만 보는 어림 규칙이라 틀릴 수 있으므로 지우지는 않습니다. 화면의 "스팸 의심 숨기기"를 끄면 표시가 붙은 채로 원래 순위를 볼 수 있습니다.

### Hugging Face 탭

탭 안에서 **모델 · Spaces · 데이터셋**을 오갑니다. Hugging Face API에는 "이 기간에 만들어진 것만" 거르는 조건이 없습니다. 그래서 종류마다 목록을 좋아요순으로 한 번 훑어 내려가며(한 번에 1,000개씩, 최대 60번), 각 항목을 만든 날짜가 속한 주·달·해에 나눠 담습니다. 목록이 좋아요순이므로 기간마다 먼저 담긴 100개가 그 기간의 상위 100개입니다.

- 한 번 훑으면 그 종류의 모든 기간이 함께 갱신됩니다. 종류마다 수십 초쯤 걸리고 토큰 없이도 됩니다. 세 종류가 같은 요청 한도(익명 5분에 500회)를 나눠 쓰므로 동시에 받지 않고 차례로 받습니다(분야별 순위도 같은 줄에 섭니다).
- 60번을 받고도 100개가 안 찬 기간(막 시작한 주 등)은 찬 만큼만 보여 주고, 좋아요 몇 개 이상까지 훑었는지를 함께 적습니다.
- "최대 좋아요" 탭은 만든 때를 가리지 않으므로 훑은 목록의 맨 앞 100개 그대로입니다. 같은 훑기에서 함께 담기므로 따로 더 받는 것은 없습니다.
- 2022년 3월 이전에 만든 것은 만든 날짜가 모두 같은 날로 기록돼 있어, 기간별 순위는 2023년부터만 다룹니다. "최대 좋아요" 탭에는 그런 것도 나오는데, 생성일은 그 기록된 날로 보입니다.
- 포크가 없어 스팸 의심 규칙은 적용하지 않습니다. 대신 모델은 작업 종류·라이브러리·최근 30일 다운로드 수를, Space는 무엇으로 만들었는지(SDK: Gradio·Docker·Static 등)를, 데이터셋은 데이터의 형태(text·image·audio 등)와 다운로드 수를 보여 줍니다.
- 모델과 데이터셋은 정렬을 "다운로드순"으로 바꾸면 순위에 든 것을 최근 30일 다운로드가 많은 순으로 다시 줄 세웁니다. 다운로드순으로 따로 훑은 순위가 아니므로, 좋아요 상위 100개에 들지 못한 것은 다운로드가 많아도 나오지 않습니다. 다운로드 수가 없는 Spaces에는 이 정렬이 없습니다.
- 한 종류의 수집이 실패해도 나머지는 그대로 배포되고, 실패한 종류는 지난번 순위를 실패 표시와 함께 보여 줍니다.
- 다룰 종류는 `config.js`의 `hf.kinds`에서 고릅니다.

### Hacker News 탭

Hacker News 검색 API(Algolia 제공)는 올라온 시각으로 범위를 걸면 점수 내림차순으로 돌려줍니다. 그래서 GitHub 탭과 같은 방식으로, 기간마다 한 번 검색한 상위 100개가 그 기간의 순위입니다.

- 토큰이 필요 없고 한도가 넉넉해, 기간 88개를 몇 개씩 동시에 받습니다. 처음에는 10초 남짓, 그 뒤로는 진행 중인 기간(최근 7일·이번 주 등 6개와 전체 기간)과 다시 확인할 때가 된 지난 기간만 받습니다.
- 연간은 2007년부터 있습니다. 채용 공고와 설문은 빠집니다.
- "최대 점수" 탭은 올라온 때를 가리지 않고 검색한 결과로, 지금까지 점수를 가장 많이 받은 글 100개입니다.
- 제목은 원문으로, "댓글"은 Hacker News의 토론으로 이어집니다. 본문만 있는 글(Ask HN 등)은 제목도 토론으로 갑니다.
- 정렬을 "댓글순"으로 바꾸면 순위에 든 글을 댓글이 많은 순으로 다시 줄 세웁니다. 댓글순으로 따로 검색한 순위가 아니므로, 점수 상위 100개에 들지 못한 글은 댓글이 많아도 나오지 않습니다.
- 언어 자리에는 원문 사이트(도메인)를 보여 주고, 그것으로 거르거나 찾을 수 있습니다.
- "그 기간에 올라온 글 N개 가운데"의 N은 API가 정확히 세어 준 때만 적습니다. 글이 많은 기간은 어림값만 오는데 실제와 차이가 커서 쓰지 않습니다.
- 일부 기간만 받지 못하면 잠깐 뒤에 그 기간만 한 번 더 받아 보고, 그래도 안 되면 그 기간만 지난번 순위를 두고 표시를 남깁니다.

### App Store 탭

애플은 "이 기간에 나온 앱을 인기순으로" 주는 목록을 제공하지 않습니다. 대신 인기 차트(무료·유료·최고 매출)를 종합과 카테고리별로 100위까지 공개 피드로 줍니다. 그래서 이 탭은 기간이 아니라 차트 종류와 카테고리를 고르는 방식이고, 순위는 애플이 매긴 차트 순서 그대로입니다.

- 차트 3종 × (종합 + 카테고리 24개) = 75개 차트를 한 번에 받습니다. 요청 100여 번에 2~3분쯤 걸리고 토큰이 필요 없습니다.
- 차트에 나온 앱의 평가 수와 별점은 애플의 조회 API로 200개씩 묶어 받아 옵니다. "평가" 칸은 누적 평가 수, "증가"는 앞선 스냅샷 이후 늘어난 평가 수입니다.
- 순위 변동과 "NEW"(차트에 새로 진입)는 앞서 수집한 스냅샷과 비교한 값입니다(약 하루 전).
- 새 앱만 보려면 "출시" 거르기(최근 7일·30일·1년)를 씁니다. 오른쪽 차트는 순위에 든 앱의 출시 연도 분포입니다.
- 차트 순위는 애플의 집계(다운로드 속도 등)를 따르므로 평가 수 순서와 다릅니다. 정렬을 "평가 증가순"으로 바꾸면 최근 평가가 많이 붙은 앱을 볼 수 있습니다.
- 일부 차트만 받지 못하면 그 차트만 지난번 순위를 두고 표시를 남깁니다. App Store 수집이 통째로 실패해도 나머지 탭은 그대로 배포됩니다.
- 기본은 한국 스토어입니다. 다른 나라는 `config.js`의 `as.country`(예: `us`, `jp`)를 바꿉니다.

Google Play는 공식 차트 API가 없고 웹 페이지를 긁는 것은 약관 위반이라 다루지 않습니다.

## 분야별 순위

GitHub·Hugging Face·Hacker News 탭에서는 기간 아래의 **분야** 단추로 한 분야의 순위만 볼 수 있습니다. 기본으로 에이전트 AI, 로보틱스, LLM, 이미지·영상 생성, 음성이 있고, 맨 앞의 "전체"가 분야를 가리지 않은 원래 순위입니다. 전체 순위 100개에서 그 분야 것을 골라내는 것이 아니라, 분야마다 따로 받아 온 그 분야의 상위 100개입니다. 그래서 전체 순위에는 들지 못한 것도 나옵니다.

분야를 고른 채로 탭을 오가면 그 분야가 유지되고(그 출처에 그 분야가 있을 때), 주소 끝에 분야가 붙습니다(`#weekly/rolling/robotics`, `#hf/monthly/rolling/agents`). App Store는 스토어의 카테고리가 따로 있어 분야를 두지 않습니다.

### 모아 보기

분야를 사이트마다 따로 열어 볼 필요 없이, 맨 앞의 **모아 보기** 탭에서 한 번에 봅니다. 분야와 기간을 고르면 GitHub 저장소, Hugging Face 모델·Spaces·데이터셋, Hacker News 글의 순위가 출처마다 카드 하나씩 10위까지 나란히 나옵니다(`#mix/weekly/rolling/robotics`). 분야를 "전체"로 두면 분야를 가리지 않은 순위를 같은 방식으로 봅니다.

- 기본은 모든 곳이고, 탭 아래의 단추로 나란히 볼 곳을 켜고 끕니다. 고른 것은 그 브라우저에 기억됩니다.
- 스타·좋아요·점수는 서로 견줄 수 없는 수라 한 줄로 합치지 않고 출처별로 나눠 보여 줍니다.
- 카드의 제목이나 "100위까지 보기"를 누르면 같은 기간·분야 그대로 그 출처의 순위표로 갑니다. 거기서 모아 보기 탭을 누르면 다시 돌아옵니다.
- 출처마다 다루는 기간이 달라(Hugging Face는 2023년부터) 어떤 기간에는 일부 카드에 "이 기간의 순위는 없습니다"가 나옵니다. App Store는 기간과 분야가 없는 차트라 나오지 않습니다.
- 따로 더 받는 것은 없습니다. 출처별 순위 파일을 화면이 함께 읽을 뿐입니다.

### 화면에서 분야 더하기

분야 단추 끝의 **+ 분야 추가**를 누르고 이름과 낱말(쉼표로 나눠 6개까지)을 적으면 그 분야의 순위를 바로 봅니다. 사이트가 받아 둔 것이 아니라, 그 브라우저가 GitHub·Hacker News·Hugging Face에 직접 검색한 결과입니다.

- 이렇게 더한 것은 **내 분야**로, 그 브라우저에만 저장됩니다(점선을 두른 단추). 다른 기기나 다른 사람에게는 보이지 않습니다.
- 적은 낱말을 모든 출처에 씁니다. "출처마다 다르게 적기"를 펼치면 GitHub, Hacker News, Hugging Face 태그, Hugging Face 이름을 따로 적습니다. 비워 둔 출처에는 그 분야가 나오지 않습니다.
- 고른 분야 옆의 **고치기**로 낱말을 바꾸거나 지웁니다. 사이트에 등록된 분야도 고칠 수 있는데, 그러면 그 브라우저에서는 고친 낱말로 바로 검색한 결과를 봅니다("고친 것 버리기"로 되돌립니다).
- 바로 검색한 순위에는 증가와 순위 변동이 없습니다(견줄 지난 값이 없습니다). 한 번 검색한 것은 10분 동안 다시 묻지 않고, "다시 검색" 단추로 새로 받습니다.
- GitHub 검색은 로그인 없이 분당 10회까지입니다. 여러 기간을 잇달아 열다 한도에 걸리면 언제 풀리는지 알려 주고 그때 다시 받습니다.
- Hugging Face에는 만든 날짜로 거르는 검색이 없어, 조건마다 좋아요가 많은 것부터 5,000개까지만 훑습니다(사이트의 수집은 2만 개까지). 아주 큰 태그에서는 좋아요가 적은 최근 것이 빠질 수 있습니다.

#### 정식 분야로 등록

내 분야를 보는 화면의 **정식 분야로 등록**을 누르면 그 분야가 적힌 GitHub 이슈 작성 화면이 열립니다. 그대로 제출하면 워크플로(`.github/workflows/category.yml`)가 `categories.json`에 반영해 커밋하고 배포를 돌린 뒤, 결과를 답글로 달고 이슈를 닫습니다. 몇 분 뒤부터는 사이트가 하루 두 번 받아 두는 분야가 되어 어느 기기에서나 보이고, 증가와 순위 변동도 나옵니다.

- **저장소 주인이 올린 이슈만** 처리합니다(제목이 `[분야]`로 시작하는 것). 다른 사람이 올린 이슈는 아무 일도 일으키지 않습니다.
- 이슈 본문은 믿지 않습니다. 정해진 모양의 JSON만 읽고, 낱말에 쓸 수 있는 글자와 개수를 화면과 같은 규칙(`public/live.js`)으로 확인합니다. 맞지 않으면 까닭을 답글로 달고 닫습니다.
- 분야는 12개까지 둘 수 있습니다(`config.js`의 `categories.max`). 분야 하나마다 GitHub 검색을 기간 35개만큼 더 쓰기 때문입니다.
- 사이트에 등록된 분야는 "고치기" → **사이트에서 지우기**로 지웁니다(같은 방식의 이슈가 열립니다).
- 등록한 뒤 아직 받아 오지 못한 기간은, 그동안 화면이 바로 검색한 결과로 보여 줍니다.
- 이 워크플로는 `main`에 커밋할 권한(`contents: write`)을 씁니다. 워크플로가 올린 커밋은 푸시 때의 배포를 일으키지 않으므로 배포 워크플로를 직접 돌립니다(`actions: write`).
- 로컬 서버(`npm start`)에는 등록 단추가 없습니다. `categories.json`을 직접 고치고 서버를 다시 띄웁니다.

### 분야를 가리는 방법

분야는 낱말로 가립니다. 출처마다 가리는 방법이 다릅니다.

- **GitHub**: 이름·설명·토픽에 그 분야의 낱말이 하나라도 든 저장소를 같은 방식으로 검색합니다(`robot OR ros2 OR … in:name,description,topics`). GitHub 검색이 OR를 다섯 번까지만 받으므로 낱말은 분야마다 6개까지입니다. 스팸 의심 규칙도 그대로 적용됩니다. 검색 한도는 전체 순위와 나눠 쓰는데, 수집기를 가리지 않고 급한 것부터 받습니다: 아직 없는 첫 화면(분야마다 최근 구간), 진행 중인 기간의 갱신, 아직 없는 지난 기간, 지난 기간의 재확인 순입니다.
- **Hugging Face**: 그 분야의 태그가 붙은 것과 이름에 그 분야의 낱말이 든 것을, 조건마다 좋아요순으로 훑어(조건마다 최대 20번, 2만 개) 합친 뒤 만든 날짜로 기간에 나눠 담습니다. 좋아요가 하나도 없는 것은 싣지 않습니다. 상한에서 멈춘 조건이 있으면 모든 조건에서 빠짐없이 본 좋아요 수 이상인 것만 순위에 넣고, 덜 찬 기간에는 어디까지 훑었는지를 적습니다.
- **Hacker News**: 제목에 그 분야의 낱말이 든 글을 낱말마다 따로 검색해 합친 뒤 점수순으로 다시 세웁니다. 낱말의 앞부분만 같아도 찾습니다(`agent`로 agents, agentic도). 띄어 쓴 낱말은 그 구절이 그대로 든 글만 찾습니다. 낱말이 여럿이면 겹치는 글이 있어 "N개 가운데"의 N은 적지 않습니다.

알아 둘 점:

- 낱말로 고르는 것이라 다른 뜻으로 쓰인 것이 섞이거나(예: voice), 그 낱말을 쓰지 않은 것이 빠질 수 있습니다. 무엇으로 골랐는지는 화면 아래 설명에 적혀 있습니다.
- 받는 양을 줄이려고 기간 목록을 짧게 둡니다: 주간은 지난 4주, 월간은 지난 6달까지이고(전체 순위는 26주·36달), 연간과 "최대 …" 탭은 같습니다. 끝난 기간은 하루~30일에 한 번만 다시 확인합니다.
- 분야를 처음 켜거나 새로 더하면 GitHub 쪽은 분야마다 기간 35개쯤을 하나씩 채워야 해서, 예약 빌드 몇 번(하루 이틀)에 걸쳐 채워집니다. 최근 구간부터 채우고, 아직 못 받은 지난 기간은 화면에 "아직 받아 오지 못한 기간"으로 보입니다. Hugging Face와 Hacker News 쪽은 첫 빌드에 모두 받습니다.
- 한 번 거절당한 요청은 잠깐 뒤에 한 번 더 보냅니다(조건을 건 Hugging Face 목록은 처음 부를 때 "오래 걸린다"며 거절하는 일이 있습니다). 그래도 실패한 분야는 지난번 순위를 그대로 두고, 나머지는 그대로 배포됩니다.

분야 목록은 저장소의 `categories.json`에 있습니다. 화면에서 등록하면 워크플로가 이 파일을 고치고, 직접 고쳐도 됩니다. 적힌 순서대로 화면에 나옵니다.

```json
{
  "id": "robotics",
  "label": "로보틱스",
  "github": ["robot", "robots", "robotics", "ros2", "humanoid", "embodied"],
  "hf": { "tags": ["robotics", "task_categories:robotics"], "search": ["robot"] },
  "hn": ["robot", "humanoid"]
}
```

- `id`: 주소와 폴더 이름에 씁니다. 영문 소문자로 시작하고 소문자·숫자·`-`만 씁니다.
- `label`: 단추에 보일 이름입니다.
- `github`: 저장소의 이름·설명·토픽에 든 낱말(6개까지).
- `hf.tags`, `hf.search`: 붙은 태그와, 이름에 든 글자.
- `hn`: 글 제목에 든 낱말.

어느 출처의 낱말을 적지 않으면 그 출처에는 그 분야가 나오지 않습니다. 잘못 적은 분야(id 형식, 낱말 수 등)는 서버와 빌드가 시작할 때 오류로 알려 줍니다. `categories`를 `null`로 두면 분야 없이 돕니다. 분야별 순위의 파일은 `data/<출처>_<분야>/`(예: `data/gh_robotics/weekly.rolling.json`)에 놓이고, 수집 상태도 그 아래 `state/`에 함께 올려 다음 빌드가 이어받습니다.

## 내 컴퓨터에서 돌리기

Node.js 18 이상이 필요하고, 설치할 패키지는 없습니다.

```sh
npm start        # 로컬 서버: http://127.0.0.1:4173
npm run build    # 정적 사이트를 site/ 에 만든다
npm test         # 로직 시험(바깥 API를 부르지 않는다)
```

로컬 서버는 같은 화면을 쓰되, 백그라운드에서 수집하면서(진행 중인 기간은 한 시간에 한 번, 보는 사람이 없으면 더 드물게) 바뀐 순위를 실시간으로 밀어 주고(SSE), 목록에 없는 오래된 기간도 열 때 받아 옵니다. 분야별 순위도 함께 수집하는데, 토큰이 없으면 GitHub 검색이 분당 10회라 분야별 순위가 다 채워지기까지 한 시간쯤 걸립니다(연 화면의 것부터 받습니다).

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `GITHUB_TOKEN` (또는 `GH_TOKEN`) | 없음 | 있으면 검색 한도가 분당 10회에서 30회로 늘어납니다. 권한(scope)은 필요 없습니다 |
| `HF_TOKEN` | 없음 | Hugging Face 토큰. 없어도 됩니다(익명 한도 5분에 500회, 세 종류를 훑는 데 180회 이하) |
| `PORT`, `HOST` | `4173`, `127.0.0.1` | 로컬 서버 주소 |
| `SEED_URL` | 없음 | 빌드가 수집 상태를 이어받을 배포본 주소(Actions가 넣어 줍니다) |
| `BUDGET_SEC` | 540 | 빌드 한 번이 수집에 쓰는 시간 상한(초) |
| `GITHUB_REPOSITORY` | 없음 | 이 사이트를 만드는 저장소(`주인/저장소`). 있으면 화면에 "정식 분야로 등록"이 나옵니다(Actions가 넣어 줍니다) |

갱신 주기, 기간 목록 길이, 스팸 의심 기준 같은 값은 `config.js`에서 바꿉니다. Hugging Face, Hacker News, App Store 탭을 빼려면 `config.js`의 `hf`, `hn`, `as`를 `null`로 둡니다. 분야는 화면에서 등록하거나 `categories.json`에서 고칩니다(위 "분야별 순위"). 수집 시각을 바꾸려면 워크플로의 `cron`(UTC)과 `config.js`의 `static.every`·`static.at`을 함께 바꿉니다(회차 사이는 1시간 이상 12시간 이하).

## 구조

```
.github/workflows/pages.yml  예약 실행: 수집 → 정적 사이트 → Pages 배포
.github/workflows/category.yml  화면에서 등록한 분야(이슈)를 categories.json에 반영하고 배포를 돌린다
scripts/build.js             정적 사이트 빌드 실행
scripts/category.js          이슈 본문을 읽어 categories.json을 고친다
categories.json              분야 목록(화면에서 등록하거나 직접 고친다)
lib/build.js                 빌드: 지난 배포본에서 상태 이어받기, 수집, 파일 쓰기
lib/collector.js             GitHub 수집기: 우선순위, 한도 관리(분야별 수집기와 나눠 쓴다), 백오프
lib/sources.js               GitHub 말고 덧붙는 출처 목록(hf·hfs·hfd, hn, as)과 분야별 순위(<출처>_<분야>): 서버와 빌드가 이것으로 수집기를 만든다
lib/categories.js            분야별 순위의 설정 읽기와 검증, 목록 고치기
lib/sweep.js                 한 번 훑어 모든 목록을 갱신하는 수집기의 공통 뼈대
lib/hfcollector.js           Hugging Face 수집기: 좋아요순 목록을 훑어 기간에 나눠 담기
lib/hncollector.js           Hacker News 수집기: 기간마다 점수순으로 검색
lib/ascollector.js           App Store 수집기: 차트 피드를 받고 평가 수를 묶어 조회
lib/store.js                 순위 캐시, 증가·순위 변동 계산
lib/periods.js               기간(버킷) 정의와 갱신 주기
lib/github.js                GitHub 검색 API 호출
lib/hf.js                    Hugging Face 목록 API 호출(모델, Space, 데이터셋)
lib/hn.js                    Hacker News 검색 API 호출
lib/appstore.js              App Store 차트 피드와 조회 API 호출
lib/spam.js                  스팸 의심 판정
public/                      화면(HTML·CSS·JS, 빌드 과정 없음)과 홈 화면에 추가할 때 쓰는 이름표(manifest.webmanifest)·아이콘(PNG)
public/live.js               분야를 적는 규칙과, 브라우저가 바로 검색하는 부분(화면·시험·등록 스크립트가 함께 쓴다)
server.js                    로컬 서버(실시간 푸시, 수동 갱신)
config.js                    설정
test/                        로직 시험
```

`data/`(로컬 캐시)와 `site/`(빌드 결과)는 실행하면서 생기며 저장소에 올리지 않습니다.
